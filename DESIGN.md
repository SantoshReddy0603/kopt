## What is implemented

The optimizer uses explicit control-flow edges and integer operands. Register operands and literals have disjoint representations. The parser resolves labels and checks the KIR grammar. The writer preserves the function name, parameter registers and their order, and the entry label.

The implementation includes jump threading, unreachable block removal, adjacent block merging, constant and copy propagation, algebraic simplification, local value numbering, common expressions across control-flow edges, liveness, safe removal of dead instructions, scratch store elimination, memory forwarding, strength reduction, fused instructions, collapsing of linear sums, splitting of serial Horner chains, signed division and remainder by powers of two without `div`, branch-free population counts in place of bit-counting loops, GF(2)-affine rebuilding of straight-line xor/shift/mask code, conversion of small branches to `select`, 0/1 arithmetic in place of selects, loop rotation, deferred remainders in counted loops, loop invariant hoisting, counter range rewrites, induction strength reduction, full and partial loop unrolling, grouped loop iterations under one guarded test, interval range analysis for dead loads, finite-domain lookup tables and bit-test trees, closed-form polynomials, bit-vector closed forms (masked shifts, bit permutations and population counts), path-splitting symbolic execution, copy coalescing, instruction scheduling with block-local renaming, block-local register reuse, global register renaming for small register files, and block layout.

`src/kirlib.py` adapts the organizer’s parser, machine reader, interpreter, and timing model. `src/ir.py` supplies the KIR writer. The published design headings and machine rules follow the kit. [Organizer kirlib.py](https://github.com/rudra-shroff06/LLH-26/blob/d23ac1d865df4cdacf7ad8e9fff3e1d560761c46/Compilers/COMP10/kirlib.py) · [KIR specification](https://github.com/rudra-shroff06/LLH-26/blob/d23ac1d865df4cdacf7ad8e9fff3e1d560761c46/Compilers/COMP10/KIR_SPEC.md) · [Submission rules](https://github.com/rudra-shroff06/LLH-26/blob/d23ac1d865df4cdacf7ad8e9fff3e1d560761c46/Compilers/COMP10/RULES_AND_SUBMISSION.md)

Background: the bit tricks (SWAR population count, signed division by powers of two, division by a constant through its multiplicative inverse) are the standard ones described in H. S. Warren, *Hacker's Delight*; value numbering, liveness, list scheduling and graph-coloring register allocation are textbook compiler techniques. No compiler framework, solver or code from other projects is used.

## Pass order

The command reads the program, machine and optional profile. It simplifies control flow, computes constants, rewrites expressions and memory operations, and removes newly unreachable blocks. It then looks for common expressions across edges and uses liveness to remove dead definitions and combine adjacent instructions.

For smaller programs, small branch arms can first become `select` instructions, which can turn a loop with a conditional body into a single block. Conversion repeats up to three times with block merging in between, because converting an inner diamond can leave its parent with two small arms; selects between 0/1 values are then rewritten as plain arithmetic. Loop rotation runs next: a short loop test is copied into each latch that jumps to it, so single-block bodies become self loops with a preheader. Self loops that count bits (`x &= x - 1` or shift-out) then become a branch-free population count. The loop rewrites are followed by another value and liveness analysis to take advantage of the new definitions. Signed division and remainder by a literal power of two are expanded into shifts and masks when the machine's divide latency is higher. Serial multiply-add (Horner) chains are then split into two or four independent chains in a power of x. Copies whose two registers are each written once are coalesced. Scheduling, register reuse and layout come after the semantic rewrites. Internal flags let tests isolate rewrites. The output is parsed again and checked against the target machine before it is written.

For small programs and larger programs with a short path to a return or explicit trap, a bounded set of synthetic inputs compares the original and candidate. The timing model uses the original file layout, including unreachable instructions. Candidates must preserve the sampled behavior, improve total cycles and avoid increasing cycles on any sampled run that finishes within the probe budget. Runs that end in a trap may be one taken-branch penalty slower, since moving a trap block off the fall-through path is what speeds up the other runs. Candidates come from eight rewrite variants (the default, one without loop rotation, Horner splitting or division expansion, one with `select` conversion, one with `select` conversion but no rotation, one with every rewrite except grouped loop iterations, one whose unrolling may exceed the cache estimate, one without copy coalescing, and one with every rewrite), from the path-splitting rewrite (also in a form that keeps the larger side of each split on the fall-through path), and from scheduling the original, each with and without global register renaming and with two placements: one that never makes the program name more registers than max(K, its current count), and one without that limit. When one of the rewrite variants is a single block whose result is a GF(2)-affine function of the inputs, its rebuilt form (with and without scheduling) is also a candidate. A last group places every distinct rewrite variant with eager register sharing everywhere and register pressure that counts registers live into a block, with and without global renaming; it is judged only on whole simulated runs, like every other candidate. The best accepted candidate wins; between equally fast candidates, one that fits in the machine's registers replaces one that does not, because the synthetic inputs touch few registers and can hide reloads. If no candidate passes these checks, the original bytes are retained.

Before that search, the specializing rewrites (lookup tables, polynomials and bit-vector closed forms) are tried on the original and on the rewritten program. They are exact for every input by construction, so their candidates are timed on 48 deterministic edge and pseudo-random argument sets instead of being vetoed per run. A specialized version is kept only if it is faster than the original on those arguments, and it is compared against the best probed candidate on the same arguments at the end. Each rewrite has its own safety conditions for unsampled inputs.

The command always tries to leave a valid output. An unreadable or malformed profile is ignored. If any rewrite raises an unexpected error, the input is written unchanged. The candidate search stops at a fixed work limit that depends only on the input. Nothing reads the clock.

## Each pass

| Rewrite | Safety condition | Work bound |
|---|---|---|
| Control flow | Thread only blocks that contain an unconditional jump. Keep the first block, traverse the explicit successors, and merge only adjacent reachable blocks when the target has exactly one predecessor. | Linear in instructions and edges. |
| Constant and copy propagation | Carry a constant across an edge only when all incoming paths establish that value. Read operands before defining the destination. Inside a block, a copied value can use another register only while that register holds the same value. | Bounded sparse dataflow, tracking up to 64 registers across edges with a deterministic work budget. Local tracking is linear in instructions under ordinary dictionary costs. |
| Algebra and common expressions | Evaluate literals with 32-bit wrapping, signed comparison and truncating signed division. Local keys use value identities. Across blocks, each immediate predecessor must establish the same expression in the same register and leave its operands intact. The receiving block must not have overwritten those registers. | Linear in instructions and edges with bounded predecessor summaries. |
| Memory | Reuse a load value only if a prior access to the same address succeeded and no intervening effect can change it. Unknown stores invalidate remembered addresses. Scratch writes may be removed when overwritten before a read, or before a function exit with no read. | Linear in the block length under ordinary dictionary costs. Constant address facts are bounded by the address space. |
| Liveness and combining | Remove a definition only if its value is dead and the operation has no visible effect and cannot trap. Retarget an adjacent producer and copy when the intermediate is dead. Fuse a multiply or shift with an adjacent add only when the intermediate has a single relevant use and the target supports the instruction. | Backward worklist with an instruction-based work and memory budget. Final backward walks are linear. |
| Loops | Work on single-block natural loops with a unique unconditional preheader. Hoist pure invariant definitions that cannot affect an earlier read. An induction rewrite maintains the product modulo 2³² in a fresh register. Unrolling needs a proven signed trip count without wraparound, a known start value, and space in the cache estimate (one probed variant allows eight more copies of the body). Up to eight iterations become straight-line code. Longer loops repeat the body 8, 4 or 2 times per test, and the remaining iterations are copied once into the preheader. Each copy executes the same instructions in the same order as the original iterations, so loads, stores, volatile operations and traps keep their order. | Bounded work per loop plus a linear scan and sorting of candidate loops. |
| Linear sums | A value built only from add, sub, constant mul or shl, constant `mac`, `addsh`, mov and const is a sum of block inputs times constants modulo 2³². It is recomputed from the inputs only if every input still holds the value the sum refers to, the instructions that built it are read nowhere else in the program, and the new sequence is shorter. Fresh registers hold intermediate terms. | One pass per block; sums with at most three inputs. |
| Horner splitting | A chain of at least four steps r' = r*x + t (`mac`, or `mul` then `add` whose product has one reader) in one block, with the same value of x in every step, becomes k = 2 or 4 Horner chains in y = x^k joined as C1*x + C0 or (C3*x + C2)*x^2 + (C1*x + C0); a literal 0 start value is dropped. k is chosen by an estimated latency, lat_mul*log2(k) + (ceil(T/k) - 1)*step + join against (T - 1)*step, and only when k + log2(k) + 3 registers fit the machine. | 32-bit wrapping arithmetic is a commutative ring, so the value is exact for every input. Every replaced intermediate and product has a single reader in the chain and is not live after the block; x is not written between the first multiply and the last step; a term defined in the block and read only by its step gets a fresh name, other terms are read where unchanged or copied. Only pure instructions are replaced or added. Blocks of 8 to 4,000 instructions, one linear scan per block. |
| Select conversion | A block ending in `br c` whose arm blocks have no other predecessor, jump to a common join and hold at most four calculations or loads, runs the arms in place of the branch and picks each register live at the join with `select`. One arm writes in place only where the other arm and the selects no longer need the old value; everything else gets a fresh register. A load is allowed only from a literal address below 4096 or from an address register already used by a load or store in the branching block and not changed since, so the speculative load cannot trap. Arms never store, divide or touch volatile ports, and the condition register is never overwritten. | Probed variants only, because extra registers or a longer critical path can cost more than the branch. At most three rounds. |
| Select arithmetic | A register is boolean at a point when its latest definition in the block is `lt`, `eq`, `and r, 1`, a 0/1 constant or one of the 0/1 forms below, or when every definition in the program yields 0 or 1 (registers start at 0). Rules: select(c, 1, 0) = c; select(c, 0, 1) = eq c, 0; for boolean c and y, select(c, y, 0) = and c, y, select(c, 0, y) = lt c, y and select(c, 1, y) = or c, y; select(c, a + s, a) = a + select(c, s, 0) (and the mirrored form) for s = 1 or boolean, which holds for every a because addition wraps; eq(eq(a, 0), 0) = lt 0, a when a is boolean or masked by a literal below 2³¹; and(x, eq(b, 0)) = lt b, x for boolean x and b. When no rule applies, a select whose condition is eq(b, 0) tests b with the arms swapped, and one whose condition is eq(b, 1) for boolean b tests b directly (up to four levels), which removes one step from bit-serial chains such as CRC loops. A definition is looked through only when none of its operands is written again before the use. Every rule replaces a pure instruction by a pure one with the same value. | One pass per block; skipped when fresh register numbers would run out. |
| Deferred remainders | A counted self loop (`add i, i, s` with literal s, then `lt c, i, n; br c`) with a known constant start, and a limit that is a literal or has a proven range, may drop its `mod r, x, M` for one literal M. The body is run on upper bounds for the largest trip count: every possibly unreduced value may only be copied, added to another such value or to a value with a known non-negative bound, or fed into a dropped `mod`, and every sum must stay below 2³¹; values entering the loop must be known constants below M. Addition keeps values congruent modulo M and the signed `mod` of a value in 0..2³¹−1 is the ordinary remainder, so taking the remainders once on a new exit block, for every such register live there, gives the same values. A literal M > 0 never traps. | Bodies of at most 64 instructions, at most 4,096 trips and 200,000 simulated instructions per loop, programs of at most 4,000 instructions. |
| Copy coalescing | `mov a, b` is dropped and a renamed to b when a and b are each written exactly once, the copy follows b's definition in the same block, a is not read there before the copy, and neither is a parameter. Every register starts at 0, so on every path the two are either both unwritten or equal. | Four rounds, programs of at most 30,000 instructions. |
| Grouped iterations | A single-block loop ending `add i, i, s; ...; lt c, i, n; br c` where i is written only by that add and s and n are literals or registers the body never writes. With D = 3s and t = n − D, an iteration starting with i < t (signed) passes the next three loop tests, because i grows by a positive step and stays below n without wrapping. The preheader computes t once and sets it to the smallest signed value, so the guard always fails, when s is not in 1..2²⁸−1 or n − D would wrap. A group block runs four copies of the body and loops while i < t; otherwise the original loop finishes, entered through a block that repeats its last test. Every executed instruction is one the original would execute, in the same order. | Only loops that were not unrolled, within the cache estimate; eight fresh registers; one variant without it is probed. |
| Loop rotation | Copy a loop test of at most eight instructions into each latch that ends in a jump to it, lies on a cycle through it and is dominated by the loop head (unreachable from the entry without passing the head). This duplicates straight-line code before the same branch, so every path runs the same instructions in the same order. A new empty preheader is added only when the body becomes a self loop. | One reachability walk per latch candidate; predecessor lists are updated in place. |
| Counter ranges | A loop counter that starts at a known constant in 0..2³¹−1, changes only through one `add c, c, k` with k > 0, and controls the loop with a signed `lt` never becomes negative. When k is 1, or the limit is a literal at most 2³¹ − k, the add cannot wrap. Then `div c, 2^m` becomes `shr` and `mod c, 2^m` becomes `and`. The start value is found by walking back through blocks with exactly one predecessor; an unwritten non-parameter register in the entry block is 0. | A walk over single-predecessor chains, visiting each block once. |
| Range analysis | Forward interval analysis of unsigned ranges. Branches on signed `lt` (both sides known non-negative), on `eq` and on a register narrow the ranges along each edge, unless the condition register is one of its own operands or an operand is redefined later in the block. Loop heads widen after three visits to the next threshold (a program literal, 4095, 2³¹−1 or the full word), then two narrowing rounds recover counted bounds. A load whose address is always below 4096 cannot trap, so it can be removed when its value is dead. | At most 30,000 instructions and a worklist budget of 64 visits per block. |
| Population-count loops | A block that branches to itself and contains only pure instructions, at most 24, where one register x becomes `x & (x - 1)` (or `x >> 1` logical, with a counter adding `x & 1`), counters add a nonzero literal, and the back edge is taken exactly when the new x is not zero (tested directly or through `eq(…, 0)` chains, found by symbolic evaluation of the block). The loop is replaced by c += k * popcount(x) with a 12 to 15 instruction SWAR count (multiply by 0x01010101 when `lat_mul` is at most two ALU latencies, else shifts), then x = 0. The clear-lowest loop runs once even for x = 0, so unless every entry (through empty forwarding blocks) already branches on x != 0, `eq x, 0` is added to the count; when every entry is guarded, those tests become jumps, because with x = 0 the new block adds nothing. | Every other register the body writes must be dead at the exit (liveness); x and the counters get exactly the values the loop leaves. Pure arithmetic only, so traps, memory and volatile order cannot change. Programs up to 30,000 instructions, one symbolic pass per self loop. |
| Division by powers of two | `div d, x, 2^k` with 1 <= k <= 30 becomes ((x xor m) >> k) xor m plus ((x & (2^k - 1)) != 0) and the sign bit, with m = 0 - (x >> 31); `mod` becomes l - (((l != 0) and sign) << k) with l = x & (2^k - 1). When the latest definition of x in the block is an `and` with a literal below 2^31, a logical right shift by at least one, a test or a small constant, a single `shr` or `and` is used. Applied only when `lat_div` exceeds six (division) or four (remainder) ALU latencies. | A nonzero literal divisor cannot trap, so a pure instruction is replaced by pure instructions; the formulas round toward zero and keep the sign of x exactly as `div` and `mod` do, checked over all k on edge and random values. One linear scan. |
| Bit-affine rebuilding | Each register of a single block ending in `ret` is tracked as 32 GF(2) forms (constant plus a set of input bits). Supported: const, mov, xor, and/or where one side of each bit is constant, shifts by literal or constant amounts, `eq` against a value with at most one input-dependent bit, and `select` on such a value when the two arms differ by a constant. The result becomes C xor the sum of (bit v ? M_v : 0); input bits whose M_v is one bit at the same distance are gathered into one shift and mask, the others take `and` plus `select`, and the terms are joined by an xor tree emitted like a binary counter (about log2(terms) live sums). | Any other instruction (a carry, a product of two input-dependent bits, memory, division) stops the analysis, so the forms are exact for every input. Offered only when shorter than the block; judged by the probe like every candidate. Blocks up to 1,500 instructions and 160 terms. |
| Lookup tables | Every read of a raw parameter must be an `and` with a constant mask, proven by a forward dataflow; memory and volatile instructions reject. The organizer's interpreter evaluates the original for every value of the masked bits (at most ten); any trap or timeout rejects. Results are packed into 1- to 32-bit fields of literals and picked by `select` trees or key-bit branches. A bit-test tree instead tests each key bit straight on the parameter (`and t, p, 2^b`), all at entry or one per node, branches once per internal node, picks the lowest zero to three bits with `select` over literals, ends in `ret` of a literal and shares identical subtrees. Shapes are ranked by total cycles over up to 64 argument sets whose key bits are spread evenly over the whole key range (the fixed samples when the key is not enumerable), so the choice reflects random inputs rather than small values. When the other parameters only pass through add, sub, mul, shl, `mac`, `addsh` and `select`, the evaluation keeps them as polynomials modulo 2³² (at most 12 terms, degree 4); the table then holds coefficients, or the values are rebuilt from binomial coefficients C(n, j), dividing by 2 and 4 with shifts and by 3 with its inverse 0xAAAAAAAB, in Horner form. | At most 4,000 instructions, 40,000 steps per run and 1,500,000 in total. |
| Bit-vector forms | The original runs once with every parameter bit symbolic. A value is a word, a vector of 32 positions each the XOR of parameter bits plus a constant, or an integer sum of such XOR terms. Branches, comparisons, addresses and divisors must see concrete words, so the same path is taken for every input; memory and volatile instructions reject. Vectors become masked shifts (at most ten distances) or staged swaps when output bit j is input bit j xor c; sums become multiples of SWAR population counts (at most three groups). | 20,000 steps; programs of at most 2,000 instructions. |
| Path splitting | The original runs with parameters as unknowns. Values are polynomials modulo 2³² over shared atoms (parameters, loads, volatile loads and non-polynomial operations). An unknown branch condition splits the run, and each side assumes the condition non-zero or zero for later tests of the same value; an unknown divisor splits on `divisor == 0`, whose zero side ends in the division trap. Loads and stores need known addresses: an address of 4096 or more ends the path in the address trap; a load of a word the path stored reads the stored value; any other load, every volatile operation and every store is emitted in its original order. A store is dropped when every continuation stores the same word again before ending, and scratch-word stores are dropped because later loads read the tracked value. The result is a decision tree whose leaves compute their effects and result straight-line. A second form places the larger side of every split on the fall-through path. | At most 40 paths, 150,000 steps, 3,000 output instructions, 16 terms of degree 4, and 2,000 input instructions; probed like other candidates. |
| Scheduling and register reuse | Preserve read-after-write, write-after-read and write-after-write dependencies, and keep effectful instructions ordered, except that loads and stores with literal addresses below 4096 (which cannot trap) may pass each other when the addresses differ. Reuse a register only when its interval is confined to one block, has a single definition and does not overlap the replacement interval. Before scheduling a block of 6 to 64 instructions (any loop body, other blocks up to 200 instructions in total), every definition except the last of each register may get a fresh name, since only final values leave the block; the renamed block is scheduled with register-pressure limits from K down and register reuse then folds the names back. Loop bodies are scored over two back-to-back iterations, so latency carried into the next iteration counts. One placement keeps a renamed block only while the whole program names no more registers than max(K, its original count), so the machine's reload tracking is never switched on by renaming. Besides the forward list schedules, a backward list schedule places each instruction as late as its readers allow, with priority to the longest chain above it; loads then issue exactly one latency ahead of their use, which keeps few values live. With that order a definition may take the name of a register whose last read is the defining instruction itself, and entry-block parameters that are never written, not read in any other block and not passed back around a loop lend their names after their last read. On machines with a reload penalty, when a block names more registers than the machine has, a beam search (16 partial orders, started from the block as given and from both list schedules) also orders and names loop bodies of up to 40 instructions, and in the loose placement any block of that size: it keeps the partial orders whose instructions issue earliest under the LRU reload model, and a local value takes the name of the most recently used resident register whose value is dead, so its write evicts nothing. Every dependency above still holds in the chosen order, and a name is reused only after the last read of its previous value. The backward and beam orders obey the same name limit in the guarded placement. | Dependency search and scheduling use fixed limits: blocks of at most 320 instructions and 16,384 in total; the beam search covers at most 40 instructions per placement outside the loose one and 96 in it. Register ownership is computed in one scan. |
| Global register renaming | Used only when the program names more registers than the machine has. Per-instruction liveness builds an interference graph: a definition interferes with everything live after it except the source of a copy, and everything live at entry (parameters and registers read before being written, which hold 0) interferes pairwise. Parameters keep their names. Registers are colored in smallest-last order, preferring a copy partner's color, and copies that become self copies are removed. | Skipped when block liveness exceeds its budget or the graph exceeds 400,000 edge checks. |
| Layout | Keep the entry first and all existing fallthrough edges. A block that ends in `trap` and is entered only from the branch just above it moves to the end, since the trap runs at most once while the other side may run many times. Retain each block’s cache exposure and favor chains that make more explicit edges adjacent. | Linear scans plus sorting within bounded layout regions. |

## The machine

The configuration is parsed using the kit’s keys and ranges. The instruction estimator accounts for issue width, memory ports, register count and reload penalty, instruction index and cache penalty, and per-operation latency. Placement uses the taken-branch cost and treats the next block in file order as the no-fence successor. The full timing model checks those costs together for bounded inputs.

Global register renaming runs only when the program names more registers than the `registers` value, because the timing model charges reload penalties only then. Multiplication by a power of two can become a shift. A suitable multiply or shift followed by an add can become `mac` or `addsh`. Availability and latency are checked against the supplied configuration. Loop unrolling considers branch cost and cache size. Induction strength reduction also checks register headroom.

## Keeping the behaviour

The visible result is the return value or trap kind and code, the full ordered volatile log, and words 0 through 3071 at termination. A divide or remainder with a possibly zero divisor stays in place. An ordinary load that may be the first access to an invalid address stays in place. A repeated access can reuse the value of a prior successful access under the memory checks above. Stores to data memory stay ordered and retain their values. Scratch memory is tracked as a possible source of later visible values.

Scheduling preserves the relative order of memory operations, volatile events and operations that can trap; the only exception is two ordinary memory operations at different literal addresses below 4096, which neither alias nor trap. Pure register calculations may move within a block if their register dependencies allow it. Trap and return instructions remain terminators. Reusing a local register cannot change a register read in another block. The simulator guard compares the full visible state for its inputs. The independent test interpreter checks a broader input set outside the optimizer.

## Profiles

The optional file contains `edge FROM TO COUNT` records. Layout considers counts for real edges when deciding between placements with the same number of fallthroughs. Loop candidates can be considered in hot-edge order, while the trip count and safety conditions come from the program. Missing and misleading counts cannot change which control-flow edges the program follows.

## Known problems

Cross-edge expression reuse covers values available from immediate predecessors. Hoisting, unrolling and induction rewrites need a single-block loop, possibly after rotation. Multi-block loop bodies only get rotation, unless `select` conversion makes them a single block. Path splitting needs known addresses and few branch outcomes, so loops over data-dependent memory (sorting, sieves, hashing input arrays) keep their loops. Register renaming minimizes the number of names but does not choose which values to spill when even the renamed program needs more registers than the machine has. Work limits can cause the optimizer to leave additional opportunities unused.

The block timing estimate approximates incoming register readiness and LRU state. Runtime cycle checks use bounded synthetic inputs and look for a short exit before simulating larger programs. Cycle counts on other inputs can differ, especially when control flow, memory latency, or register residency differs.

The candidate search stops on a fixed work limit (instructions checked plus simulated steps, 400,000 units, about 1.5 times the most any public program needs), so where it stops depends only on the input and repeated runs give byte-identical output.
